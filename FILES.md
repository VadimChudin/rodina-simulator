# Карта проекта — где что искать

Версия от 21.09.2026. Номера строк актуальны для текущей сборки.

```
lpzs_emulation/
├── frontend/              вся симуляция — работает и без сервера
│   ├── index.html         разметка: шапка, 5 страниц, правый док
│   ├── css/style.css      оформление
│   ├── js/plant.js        МОДЕЛЬ: механизмы, маршруты, зерно, аварии
│   ├── js/render.js       ОТРИСОВКА: canvas, спрайты, движение, фон
│   ├── js/ui.js           ИНТЕРФЕЙС: страницы, диалоги, кнопки
│   └── assets/            16 спрайтов оборудования + логотип
├── backend/               необязательный сервер FastAPI
│   ├── main.py            REST + WebSocket
│   └── plant.py           серверная копия модели линии
├── deploy/                конфиги для боевого сервера
├── Dockerfile             образ приложения
├── docker-compose.yml     стек: приложение + nginx
├── DEPLOY.md              инструкция по развёртыванию и эндпоинты
├── FILES.md               этот файл — карта проекта
├── README.md              описание проекта
├── check_ui.py            автотест интерфейса (38 проверок)
└── check_motion.py        автотест движения деталей
```

Правило разделения: **plant.js считает, render.js рисует, ui.js кликает.**
Если меняете поведение линии — идите в plant.js. Если внешний вид схемы — в render.js.
Если кнопки, таблицы и страницы — в ui.js.

## backend/ — сервер, нужен не всегда

Страница считает всё сама. Сервер нужен, когда за линией смотрят несколько
операторов с общим состоянием.

| Файл | Что внутри | Строки |
|---|---|---|
| `main.py` | Pydantic-схемы запросов | 29–77 |
| | REST-эндпоинты | 79–172 |
| | WebSocket `/ws`, снимок 10 раз в секунду | 175–184 |
| | `/api/health` — проба живости | 186–195 |
| | Монтирование статики: `/css`, `/js`, `/assets` | 202–207 |
| `plant.py` | Классы `Machine`, `Alarm`, `GrainParticle` | 37–118 |
| | Класс `Plant`, фоновый поток расчёта | 119–186 |
| | `start_cleaning_mode()` | 427–465 |
| | Каскад пуска, переход в режим работы | 540–575 |
| | `snapshot()` — что уходит в браузер | ~700–745 |

Важно: модель на сервере и модель в браузере — две независимые реализации.
Серверная знает 30 механизмов, браузерная 38. Меняете логику в одном месте —
проверьте, нужно ли второе.

## Проверка после правок

Оба скрипта гоняют реальный браузер и печатают список провалов.

```bash
python3 check_ui.py       # 38 проверок: вкладки, кнопки, настройки, аварии
python3 check_motion.py   # движение деталей в работе и замирание после стопа
```

Ожидаемый результат: `провалов: 0` и `ошибки страницы: нет`.
